## [2026-02-15] is there any implemention missint exepct welcome message for RFC 9420 that im implementing hybrid one?
Answer: Yes. Beyond Welcome, there are still several RFC 9420 gaps. The current implementation is a strong prototype for hybrid TreeKEM flows (Add/Update/Remove, Commit, PathUpdate, replay-safe sync), but not full RFC-wire-complete MLS yet. Main missing areas: (1) full MLS wire objects (`MLSMessage`, `PublicMessage`, `PrivateMessage`, `AuthenticatedContent`, content-type framing), (2) transcript hash/confirmation tag/membership tag pipeline, (3) full proposal surface (currently only Add/Update/Remove; missing PSK/ReInit/GroupContextExtensions/ExternalInit style paths), (4) RFC key schedule stages (`commit_secret`/`joiner_secret`/`welcome_secret`/epoch secret tree derivation per RFC labels and contexts), (5) RFC application-message encryption semantics (current DS app messages are transport payloads, not full MLS `PrivateMessage` processing), and (6) stricter DS-side protocol semantics (DS currently enforces signed API/auth policy and storage rules but does not validate full MLS state machine constraints). So Welcome is critical, but not the only remaining RFC-compliance work.
