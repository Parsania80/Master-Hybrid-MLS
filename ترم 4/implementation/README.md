# Adaptive Hybrid MLS TreeKEM Research Prototype

## What is this?

This repository is intended to become a reproducible Rust research prototype for a thesis experiment. It will compare normal binary Messaging Layer Security (MLS), binary MLS augmented with experimental mKyber delivery, and an experimental adaptive transition from a binary tree to a quaternary tree.

## Why does it exist?

The experiment studies whether changing TreeKEM arity can reduce measured communication cost enough to justify a real transition cost, and when an old binary delivery cover can be retired safely according to the thesis formulas.

## What problem does it solve?

The planned software will create a valid 128-member baseline MLS group, replay controlled multi-member workloads, measure real serialized costs, evaluate transition start and end rules, verify member convergence, and generate reproducible CSV, JSON, and Markdown reports.

## Current status

The Rust workspace pins the approved dependencies and contains an unchanged OpenMLS 0.8.1 baseline adapter. It can create and join a standard group, stage and merge normal Add/remove/self-update commits from multiple members, process standard messages, and encrypt application data. Independent regression tests verify epoch, authenticated GroupContext, RFC tree-hash convergence, and application delivery. The Phase 2 and Phase 4 quality gates have passed on Rust 1.93.1: locked offline format, check, strict Clippy, all targets, doc tests, release build, metadata, and the unchanged baseline regressions. The Phase 4 gate also runs bounded property tests for public mKyber wire mutations and verifies OpenMLS has only its RustCrypto feature enabled. The mKyber crate also implements `EducationalMkyber512Reference`, the paper-based `mkyber512-thesis-v1` profile: it validates the shared domain, emits exact 768/704/48-byte artifacts, and tests multi-recipient agreement, malformed input rejection, deterministic public-artifact reproducibility, and common/recipient tampering. A project-owned public regression digest is not an official KAT or interoperability vector. Normal reference calls use dedicated OS-RNG entry points; deterministic entropy is private to unit tests. Long-lived private keys and shared secrets are zeroized on drop, while temporary secret material uses scoped guards. It records component-only byte costs from actual serialized arrays: the 704-byte common component, each 48-byte recipient component, and their sum. The hybrid crate now performs complete isolated experimental path-level delivery: one mKyber encapsulation for the co-path recipient set, a context-bound 32-byte HPKE exporter secret and encapsulation per recipient, the canonical hybrid KDF input/expansion, and AES-128-GCM path-secret wrapping. Its instrumentation records actual public ciphertext lengths but zero KDF contribution. Tests reject every altered serialized delivery field, non-recipients, and group/epoch/tree-version/path-node replays without returning a path secret. It is not yet injected into an OpenMLS fork; the unchanged baseline never uses it. This is thesis-local educational reference code, not an author-approved profile or vector corpus; it makes no interoperability, audit, side-channel, security-proof, business, or production claim. Adaptive transition and a runnable experiment remain unimplemented. `SECURITY.md` records the non-standard protocol changes, threat model, interoperability boundary, X-Wing/C2PRI limitation, and unresolved assumptions. See `PROJECT.md`, `SECURITY.md`, `docs/adr/`, and `SESSION-LOG.md` for the authoritative decisions and audit trail.

## How to use it

The 128-member baseline constructor is available now: `cargo +stable run --bin bootstrap_128 --release --locked --offline -- --members 128 --seed 42 --output output/bootstrap-128`. The public seed selects committers only; it is not cryptographic entropy. After verification, the command writes create-new public artifacts under the requested `output/<run>` directory: `bootstrap_public_snapshot.json`, `bootstrap_128_summary.json`, `bootstrap_128_commits.csv`, and `bootstrap_128_report.md`. The snapshot contains public configuration/scheduling data, authenticated group metadata, the public TLS RatchetTree, occupied leaves, and the 127 actual Add KeyPackages. The CSV contains only public per-commit identity, epoch, byte-count, and delivery-count observations—not Commit bodies or ciphertexts. None of these files contain private MLS state, secret material, raw entropy, or a seed that reconstructs it.

Before the constructor reports success, it verifies 128 members at epoch 127, baseline binary arity 2 and height 7, actual occupied public leaf indexes `0..127`, common authenticated GroupContext/tree hash, and application delivery to every other member. It returns public facts only and then drops private client state; that lifecycle action is not a formal proof of upstream process-memory zeroization.

Run `cargo +stable test --workspace --all-targets --locked --offline` to verify the baseline and educational mKyber reference tests. Run `cargo +stable run -p mkyber --bin mkyber_benchmark --release --locked --offline` for the standalone reference timing smoke benchmark. It prints only the reference profile/parameters, actual public 704/48-byte component costs, and environment-dependent timing averages; it is not a production benchmark, security evaluation, or thesis experiment result. There is not yet a transition-evaluation runner or generated experiment report.

## Security and interoperability warning

This is educational thesis research software, not production cryptography, and it is not recommended for business or production use. All mKyber, hybrid path-secret, adaptive-tree, and TreeCover behavior is non-standard and experimental. Experimental modes must not claim RFC 9420 interoperability or a formal security proof.

The thesis specifically requires the post-quantum ciphertext to be transmitted and authenticated while excluding it from the hybrid KDF input. That omission is an experimental design choice and is not automatically covered by the X-Wing C2PRI security argument. Reports must never contain shared secrets, path secrets, private keys, AEAD keys, raw entropy, or seed material that reconstructs private state.
